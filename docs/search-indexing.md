# Search indexing

The public sitemap is https://nicolaslescalier.com/sitemap.xml, generated by
`jekyll-sitemap` and advertised in `robots.txt` for all crawlers.

## Automatic IndexNow notifications

The **Notify search engines** GitHub Actions workflow runs after a successful
**pages-build-deployment** on `main` (displayed as **pages build and deployment**
in the run list). It can also be run manually on `main`.
It checks the live ownership file, downloads the live sitemap, and validates the
HTML, canonical URL, and indexing directives of each page before submitting.

The first run submits all indexable sitemap pages. Later runs compare page hashes
against the last successful run and notify only new, changed, or removed URLs.
Shared template changes can legitimately affect every page. If GitHub evicts the
cache, the next run submits the current sitemap again. A failed crawl/submission
does not advance state. HTTP 202 means ownership validation is pending and does
not advance state either. The workflow summary lists the submitted URLs.

IndexNow shares notifications with participating engines. It does not guarantee
indexing or ranking, and does not replace the sitemap or Search Console.

The key in `.github/indexnow.json` is a public site-ownership token, not a GitHub
or Bing account credential. Its matching root-level `.txt` file must remain
public. No account API key or repository secret is required.

Validation before publication:

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/indexnow.py --dry-run
```

## Bing Webmaster Tools

Manage the property at https://www.bing.com/webmasters/ and submit the sitemap
URL above. Ownership may be imported from Google Search Console. Bing's Sitemaps
and URL Inspection screens show processing/indexing results; a successful
submission is distinct from completed crawling and indexing.


## Monthly visibility review

Check Bing Webmaster Tools Search Performance (queries, pages, clicks, impressions, CTR), AI Performance (citations and cited pages from the sources named in the report), Sitemaps, IndexNow, URL Inspection, Recommendations, Site Explorer, and Site Scan. Compare equivalent date ranges and separate unavailable or still-processing data from measured zeros. Run a bounded Site Scan after substantial changes and fix reproducible issues; do not change crawl controls or block URLs merely to raise a score.

Existing GA4 events distinguish `cta_click`, `booking_click`, `phone_click`, `email_click`, `form_started`, `form_submit`, and thank-you views. A click is an inquiry intent, not a funded loan. A form submission event can be an attempt; use confirmed form success and valid business records when measuring actual leads. No visitor-entered name, email, phone number, or financing amounts should be added to analytics events.

The website's service is fully online. Coverage pages are service information and must not imply physical offices. LinkedIn is outside the scope of these website updates. Real credentials and customer outcomes require factual support and permission before publication; existing fictional educational examples must remain clearly labeled.


## Build-time page audit

The Build website workflow runs `python3 scripts/check_site.py _site` after the actual GitHub Pages Jekyll build. It checks every sitemap page for self-referencing canonicals, distinct titles and descriptions, indexable crawler directives, one H1, valid JSON-LD, social URL consistency, accessible local images, inbound links, and working internal URLs and fragments. It also checks robots.txt access for major search and AI crawlers. It makes no network requests and does not equate technical eligibility with indexing or AI citations.
